# Phase 7A · Final audit and publication preparation

## Scientific audit

Version 1.0 delivers evidence retrieval and evaluation. The 20-paper interactive index uses QASPER v0.3 development data. Phase 5 used a separate, deterministic held-out sample of 40 papers and 156 questions. The 126 evidence-ranking-eligible questions are the quality denominator. All 156 contribute to latency. The paper-scoped setting searches the supplied paper. The title-cued setting searches the sampled 40-paper pool. No frozen settings, model weights, ranks, or scores were changed.

The audit checked the official archive and model SHA-256 values, index provenance, exact source spans, the protocol and population digests, denominators, percentile paper-cluster bootstrap with 2,000 draws and seed 42, and retrieval timing boundaries. README and technical-report tables were compared directly with the frozen report. Paper-scoped Recall@10 is .557 for BM25, .614 for BGE, .593 for RRF, and .695 for RRF + MiniLM. The last improves over RRF by .103 [+.052, +.155], with 900.81 ms median latency versus 11.87 ms. RRF versus BGE Recall@10 remains uncertain. Annotations are incomplete, and the sampled pool, title cue and single CPU environment limit generalization. The [technical report](technical-report.md) and [Phase 5 report](phase5.md) state the full context.

### The two latency fields

**Retrieval** adds only the measured query operations, including applicable tokenization/embedding, sparse or dense search, fusion and reranking. **Search request** starts before the app acquires the cached explorer resource and ends after assembling passage results. It can include tokenizer and index reconstruction, file hashing, vector validation or mapping, model loading, index setup and wait time for the shared query lock. It excludes browser rendering and the initial catalog load.

The user's 13.57 ms retrieval / 4,091 ms request was a single observation without a phase breakdown. A cold Chrome BGE search independently showed **20.76 ms / 2,487 ms**. In a clean staged AppTest, cold BGE was **15.25 ms / 1,934.97 ms** and a second search with a changed Top-k was **12.33 ms / 13.78 ms**. This supports initialization as a contributor. The exact breakdown of the user's request is unavailable. The captions now distinguish the timers, and benchmark latency remains the saved warm retrieval measurement.
