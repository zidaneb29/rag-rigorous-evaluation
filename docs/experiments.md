# Experiments and evaluation

The active project evaluates evidence retrieval. The [Phase 5 report](phase5.md) is the record of the frozen held-out protocol, resource-bounded sample, and results. Generation design and review rules below document the earlier feasibility investigation. The [1.5B pilot](phase4.md), [prompt recovery](phase4b.md), and [7B Colab sanity check](phase4c.md) stopped at their feasibility gates.

## Research questions and hypotheses

| Question | Hypothesis | Planned comparison |
| --- | --- | --- |
| Does fusion improve evidence retrieval across technical questions? | Sparse ranking helps with exact terms, while dense ranking helps with paraphrases. Fusion improves paragraph Recall@10. | C vs A and C vs B on identical queries and chunks. |
| Does reranking improve early evidence placement? | D improves nDCG@5 over C at a higher query cost. | D vs C with the same candidate pool and query order. |
| Does better context improve supported answers? | The dev-selected retriever improves grounded success over BM25. Gold context will recover some failures. | A vs the best of B–D by dev nDCG@5, plus reference-evidence and empty-context diagnostics on the same questions. |
| Does removing evidence affect abstention? | Abstention increases when sufficient evidence is removed. | Compare intact and audited evidence-removed contexts within a fixed generation condition. |

## Freeze before tuning

- Use the official paper-level split assignments. Use train for parser development and rubric calibration, validation for all model, chunking, threshold and prompt decisions, and test for one frozen comparison. Pin release hashes, paper and question IDs, normalization, eligibility rules, and sampling seed 42. Check near-duplicate titles, paper versions, and duplicate questions across splits using deterministic rules. Where a duplicate cluster crosses splits, quarantine it from scoring and candidate pools and publish the exclusion count. Keep reference labels separate from searchable data and build one independent corpus index per split. Verify split integrity before tuning. [Official release and evaluator](https://github.com/allenai/qasper-led-baseline)
- Primary retrieval uses the target paper as supplied scope and question text alone as the query. Secondary held-out retrieval searches the 40-paper sampled pool and supplies the target title with the question. Phase 3 compared title-cued and question-only queries on the same development pool and recorded target-document Hit@10. Keep results for the two held-out scopes separate.
- A question is answerable or unanswerable for generation if a strict majority of its original answer annotations agree on that status. Keep ties as a separately reported ambiguity stratum outside the primary estimates. For retrieval, score majority-answerable questions with at least one fully mapped, text-only evidence set from an answerable annotator. Report counts by exclusion reason and retain unmatched, mixed media, and conflicting evidence for audit. Never count unanswerable questions as retrieval misses.
- For generation, freeze up to 120 held-out questions before tuning (target 90 answerable and 30 unanswerable, with at most two per paper). Sort IDs before seeded sampling within strata, balance answerable questions across response types where possible, and report shortfalls and achieved counts. Prioritize answerable questions with eligible text evidence for paired reference-context diagnostics, and document the resulting scope. Report stratum-specific results and state the sample mix when reporting pooled rates. Keep benchmark answers, automatic evidence mappings, and reviewer-created labels separately versioned.

## Retrieval runs and scoring

Phase 5 ran A–D on identical eligible questions with the frozen 256-token cap and 32-token overlap. Phase 3 compared fusion depths 25 and 50 on development data. Phase 5 retained depth 50 and scored k = 1, 5, 10 and 20 from the same ranked lists.

Match normalized evidence strings to source paragraphs and section headings within the annotated paper. Phase 3 maps an exact, unique section heading to all nonempty body paragraphs when every paragraph is indexed. Keep paragraph-only scores as a sensitivity analysis. Duplicate, ambiguous, unmatched and non-text labels remain visible in the audit. Keep each annotator's complete text evidence set. Use the union of eligible sets as the primary binary relevance set and report complete annotated-set coverage when any one eligible set is fully covered. These labels measure agreement with annotated passages and may omit valid alternatives.

Track coverage of each annotated paragraph using the union of raw character offsets from returned chunks. A paragraph is found when its full span, excluding leading and trailing whitespace, is covered. Each chunk belongs to one paragraph. Assign binary gain at the first chunk rank that completes a gold paragraph. A later window adds no gain for that paragraph. The ideal places one completed paragraph at each earliest rank up to the number of gold paragraphs, an upper bound that can be unattainable when a paragraph requires multiple windows. Unannotated passages have zero observed gain and may still contain valid evidence. Report complete annotated-set coverage as a proxy and assess actual evidence sufficiency separately by reviewing the visible text.

- **Recall@k** is the number of unique gold paragraphs fully covered by the first k chunks divided by gold paragraph count. Report complete annotated-set coverage at the same cutoff.
- **MRR@20** averages reciprocal rank of the first chunk position that completes a gold paragraph, with zero if none completes by rank 20.
- **nDCG@k** uses binary gains discounted by log2(position + 1), divided by the ideal with all gold paragraphs first. Macro-average query-level scores and report denominators.
- **Efficiency** reports warm p50/p95 retrieval latency including query encoding, search, fusion and reranking where applicable. Phase 5 recorded model loads, indexing, bytes and peak working set separately. Its held-out run used one timed pass and the replay reused saved query timings.

## Archived generation protocol

- **Conditions.** Run BM25 and the dev-selected alternative on all sampled questions. Use paper-scoped queries throughout the primary generation study. Include D as an additional condition for the selective-risk curve if another alternative wins on validation. On eligible answerable questions, pack one complete annotated evidence set using the same budget and report how many fit. Compare it with natural context within that eligible subset. Run empty context as a diagnostic, and remove gold spans from a preselected subset of contexts that originally contained sufficient evidence. Have a reviewer confirm that remaining passages are insufficient before treating the removal as a negative. Keep this project-created perturbation separate from native negatives. Optionally add a small dev-defined paraphrase robustness panel with answer and evidence equivalence reviewed.
- **Answer quality.** Report normalized exact match or token F1 against compatible reference answers as automatic diagnostics. Use human scores of correct, partial, incorrect, or abstained. For completeness, define required information units from the references before reading model outputs and report the fraction correctly covered. Count correct abstention independently of answer quality. Define grounded success on answerable questions as fully correct with all substantive claims supported and cited, using all eligible answerable questions as the denominator.
- **Citation quality.** Review each atomic substantive claim and its cited passage links. Label each link directly supporting, contributing to joint support, insufficient, contradictory, or invalid. Joint support requires the cited set to establish the claim together. Citation precision is supporting or necessary jointly supporting links divided by all asserted links, including invalid IDs. Report claim-level missing citation rate and unsupported claim rate among substantive claims in answered outputs, plus invalid citation counts. Treat precision with no asserted links as undefined and report link counts. Determine faithfulness from visible context even where citations are absent. Deterministic validation checks IDs and formatting only.
- **Abstention.** Report coverage (answered / eligible), false abstention (abstained / answerable), and unsafe answer rate (answered / unanswerable). Track parse errors separately in the common denominator and never credit them as abstentions. Selective risk is the fraction of answered questions that are wrong or unsupported by visible evidence. Show the prompt-only operating point. For a curve, freeze a validation-defined threshold grid on the top cross-encoder logit for D and apply it as a post-generation abstention gate on held-out data. Report coverage and risk at every threshold, with risk undefined at zero coverage.
- **Review protocol.** Budget an initial 40–60 questions, with paired outputs for the selected conditions and a smaller calibration exercise on train or validation. Freeze the rubric and held-out review sample before inspecting test outputs. Blind reviewers to configuration and shuffle responses. Judge correctness against questions and references, then judge support using exact visible passages and citations. An optional second reviewer independently labels a seeded overlap, with agreement recorded before adjudication. Single-reviewer labels are subject to individual judgment and provide no inter-rater estimate. Keep human-review coverage and unresolved labels visible. Any future automated judge requires blinded calibration against human labels by answer type and audit for ordering and verbosity biases.

## Analysis and success criteria

Use these reviewer anchors in the first calibration exercise. Mark an answer **correct** when it answers the question with all required facts and no material error, **partial** when at least one required fact is correct but coverage is incomplete, and **incorrect** when the central answer is wrong, contradicted, or missing. An explicit decline without an asserted answer is **abstained**. Mark visible context **sufficient** only if its passages jointly establish the required answer without outside facts. For each substantive claim, record the supporting span or mark the claim unsupported, and score its links using the citation categories above. Record a short rationale for uncertain decisions and retain unresolved labels.

Report paired point differences with 95% percentile intervals from 2,000 paper-cluster bootstrap draws (seed 42), keeping paired outputs together. Use shared eligible populations for comparisons and report cluster counts, per-question failures, and uncertainty from small strata. Treat C vs A and C vs B on Recall@10 and D vs C on nDCG@5 as prespecified contrasts with descriptive intervals. Treat other metrics and slice analyses as secondary. Use greedy decoding for the main generation runs. Check a fixed 10-question dev subset twice for run stability, and report runtime differences when changing hardware or quantization.

Inspect whether sufficient evidence was retrieved, survived packing, and was used correctly. Classify missing evidence, context packing loss, incorrect interpretation, unsupported claims, invalid citations, and incorrect abstention. Document public-benchmark memorization risk, incomplete labels, dependence on NLP papers and target-paper cues, and subjectivity of human judgments. Empty-context performance is a diagnostic for prior knowledge and does not establish contamination.

The study succeeds when the frozen comparisons are reproducible, uncertainty and cost are reported, and evidence and generation failures can be audited. Quality improvements are empirical hypotheses. Claim an improvement only with its observed size, uncertainty, and cost.
